## 三条不可协商的设计原则

1. **颜色是索引，不是装饰。** 每个业务域一个固定色（收货蓝 / 生产橙 / 质检绿 / 出货青 / 追溯紫 / 异常红），全 App 不变；颜色永远与文字标签同时出现，禁止只用颜色表达状态。
2. **手套优先。** 所有可点区域 ≥56dp，主操作按钮 60dp 高；拇指热区内的元素不嵌套小热区；破坏性操作（作废、退出）必须二次确认且不与主按钮相邻。
3. **一屏一个决定。** 扫码后只问「确认这一袋」，确认后才进入表单；表单一次只暴露一个必填项，其余预填并标灰只读。

## 令牌的使用纪律

`tokens.json` 是唯一真相。Compose 主题、HTML 原型、设计文档三处均由此生成或与之比对：

- Compose：`android/app/src/main/java/.../ui/theme/Tokens.kt` 由脚本从 JSON 生成，禁止手写 hex。
- 原型：CSS 变量与 JSON 同名同值。
- 文档：色值与字号表直接引用 JSON，不另抄一份。

> 依据：本项目后端侧的真实教训是「规格声明的字段名 ≠ 运行时接受的键名，而门禁全绿」。设计侧同理会出「规范写的主色 ≠ 代码里的主色，而评审全绿」。
