# 吨袋标签设计方案（S06 建袋打码 · 待项目方确认）

> 提出方：WorkBuddy ｜ 2026-10-23 ｜ 状态：**待确认**（确认后派开发）
> 打印目标：快麦 KM-118BT · 203dpi · 纸宽 100mm · TSPL（经 io.vin.android 驱动库，已真机打通连接+自检）

## 一、版式（**v2 定稿候选：100mm × 100mm 正方形**，预览见会话内 SVG）

**v2 变化**（项目方确认尺寸 100×100 后重设计）：
- 二维码升级**中央大码 52mm**（v1 是 24mm 挤右下）——扫码距离更远更稳；
- 业务字段两列排布（物料/供应商 + 车牌/净重）；
- 人读码保留（次级识别）；补打红字标记保留右上。

自上而下：

| 区块 | 内容 | 数据来源（bag-gen 契约） |
|---|---|---|
| 标题行 | `江熙新材 · 原料吨袋` + `第 N / M 袋` | 固定文案 / `bag_seq`、`generated` |
| **吨袋码（大字）** | 人读格式 | `bags[].human` |
| 物料 | 物料名 | 车次预报（truck 上下文，APP 已持有） |
| 供应商 | 供应商名 | 车次预报 |
| 车牌 / 净重 | 车牌 + `XX.XXX 吨（摊算）` | 车牌 + `weight_allocated` |
| **二维码**（右侧 24×24mm） | 27 位吨袋码 | `bags[].code`（扫码即查谱系） |
| 底部日期 | 打印日期 + 到货日期 | 本地时间 + 车次到货日 |
| 补打标记（仅补打） | 红字 `补打·<原因>` | reprint 的 `reason`（防一物两码留痕） |

## 二、待项目方确认的 4 点

1. **标签纸实际尺寸**：宽 100mm 确认，**高多少 mm**？（版式按 60mm 设计，可等比调整）
2. **供应商**要不要上标签？（建议保留——现场识别到货来源）
3. **二维码内容**：27 位吨袋码（APP/PC 扫码即查谱系）——是否符合追溯设计？
4. **补打标记**：补打标签显示红字「补打 + 原因」小字（防一物两码留痕）——要吗？

## 三、技术要点（确认后开发依据）

- TSPL 经 io.vin.android 驱动库的 `IBluetoothPrinterProtocol`（drawText/drawQRCode/printAndFeed），与自检打印同通道（已真机验证）；
- 中文经库协议层渲染（自检标签已验证中文正常）；
- 重量 3 位小数（契约口径，摊算值标注「摊算」）；
- 建袋多袋时：每袋一张，自动连打 N 张（袋序递增）；
- 补打：走 `label/reprint`（必填原因），标签带补打标记。
