方案 A · 色块工作台（推荐）

把「岗位今天要干什么」压成一屏 4 个彩色入口。颜色即岗位、即业务域，工人不看字也能秒认位置；点进去就是该业务的作业流。

优势

  • 入口面积足够大（2×2，单块 132dp 高），戴手套点击容错最高
  • 颜色编码固定，培训一次即可形成肌肉记忆
  • 扩展性好：新增业务＝加一个色块，不推翻布局

代价

  • 「今天该做哪几件事」需要逐个色块点进去才知道，入口页信息偏弱
  • 色块数量超过 6 个时，第一屏会开始拥挤

适合谁

  • 收货员（动作固定 4 类，重复率高）
  • 质检员（取样 / 录值 / 留样 三条线并行）
✓ 推荐：四个岗位通用，培训成本最低

方案 B · 今日任务流

首页不是功能目录，而是「今天要做的活」按时间排开。工人从第一条往下做，做完一条划掉一条；扫码作为唯一常驻主按钮。

优势

  • 「现在该干什么」零思考，适合新人 / 换班交接
  • 进度可视化，班组长一眼看出卡在哪一步
  • 天然承载「下一步」引导，误操作率最低

代价

  • 依赖后端「我的待办」聚合接口——现有 API 需拼装，接不通时首页会空
  • 临时插入的活（如领导临时要查一个样）没有位置
  • 任务多时列表变长，找特定功能要往下翻

适合谁

  • 生产班组（跟着批次节奏走）
  • 上岗 3 天内的新人
△ 次选：流程引导最强，但更依赖后端聚合能力

方案 C · 大按钮控制台

工业 PDA 风格：一屏 6 个巨型色块，每个占 1/6 屏、图标 48dp、文字 21sp。功能最少、字符最少、误触最少，代价是扩展性差。

优势

  • 戴厚手套、隔着防尘面罩也能一次点中
  • 字符最少，老工人不认字也能靠颜色 + 图标操作
  • 强光下可读性最好

代价

  • 6 格封顶，加功能就要翻页或挪进二级
  • 信息密度过低，质检员的参数录入页会与首页风格断裂
  • 「待办多少」这类数量信息没地方放

适合谁

  • 纯搬运型岗位（只有 3–4 个动作）
  • 临时工 / 外包工轮换频繁的产线
△ 备选：上限低，建议只作为「收货岗专用模式」

三方案差异速览

一眼看懂

  • A：入口看颜色和数量（这活有多少待办）
  • B：入口看顺序和进度（下一步做什么）
  • C：入口看位置和大小（闭眼也能点中）

与现有后端的关系

  • A / C：全部依赖已有列表与扫码接口，零后端改动
  • B：需要「我的待办」聚合，需后端配合或客户端多次拼装

我的建议

  • 主体走 A（四岗通用、扩展性强）
  • 把 B 的「进行中任务 + 进度条」做成 A 首页顶部的一条横向卡片
  • C 的大图标 + 高对比作为全局规范继承
