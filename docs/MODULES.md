# APP 开发模块划分（v1.2）

> 定稿日期：2026-10-19（v1.2）。用途：把 16 屏拆成可独立交付、可独立验收的开发单元。
> 协作模式沿用后端：**WorkBuddy 设计 + 验收，mimo 实现**，唯一通道为任务包 `MIMO-NEXT-BATCH-NN.md` + 回执 `MIMO-DONE`。

## 0. 分模块的三条原则

1. **一个模块 = 一次可验收的闭环**，不是一层技术架构。所以「扫码」是模块，「网络层」不是（它属于地基）。
2. **跨模块依赖只允许向下**：后一个模块只能依赖前一模块已验收的公开能力（组件、Service 接口），不许反向改前一个模块。
3. **每个模块自带三条状态**：无权限、断网、空态。缺一条不算交付。

## 2. 各模块范围与验收判据

### M01 工程骨架与 CI（B1）

**做什么**
- Kotlin + Compose 工程（包名 `cn.hunanjiangxi.jxlabtrace`，minSdk 26 / target 35）。
- GitHub Actions：`./gradlew assembleDebug` → 上传 `app-debug.apk` artifact（90 天）。
- 网络层：OkHttp + CookieJar（读写 `jx_sid`）+ 统一错误模型（网络 / 401 / 403 / 业务码 / 解析失败五类）。
- 请求前置联通探测（HEAD `/healthz`，2s 超时）——断网时直接给出 M12 的拦截，不发真实请求。
- 应用级日志（环形缓冲 500 条，供「我的」页导出排查）。

**不做**：任何业务页面；任何 UI 主题细节。

**验收判据**
1. CI 绿，Artifacts 里有可安装的 APK，`versionName` 与提交号一致。
2. 无网络时发起任一请求 ⇒ 全局错误类型为 `Offline`，**不产生 OkHttp 超时等待**（日志可见前置探测拦截）。
3. 401 / 403 / 500 / 业务错误码四类，都能被解析成含 `message` 的领域错误对象（单测覆盖）。

### M02 设计系统落地（B1）

**做什么**
- 由 `design/tokens.json` **生成** `Tokens.kt`（脚本 `scripts/gen_tokens.py`，CI 校验生成物与源一致）。
- 12 个基础组件：`DomainBlock`（色块入口）、`NowBar`（进行中）、`StatusPill`、`FieldCard`（字段卡）、`BigButton`、`NumPad`（大数字键盘，过磅/取样量用）、`EmptyState`、`InterceptPage`（拦截页）、`TopBar`、`TabBarWithScanFab`、`Skeleton`、`Toast+Haptic`。
- 图标集（24 个，矢量），按业务域着色。

**不做**：页面级组合；导航。

**验收判据**
1. 全仓 `grep -rn "#[0-9A-Fa-f]\{6\}" android/app/src` 命中数 = 0（除生成物 `Tokens.kt`）。
2. 所有组件最小触控区 ≥56dp；`BigButton` 高 60dp（单测断言 layout 尺寸）。
3. `Tokens.kt` 与 `tokens.json` 逐键一致（脚本比对，差异即红）。
4. 组件在 360dp 宽下不溢出（`@Preview` 三个宽度：360 / 390 / 411）。

---

### M03 会话与权限（B2）

**做什么**
- S01 四态：初始 / 授权中 / 失败（分因）/ 成功过渡。
- WebView 完成 `/api/auth/feishu/start`，读 Cookie 注入请求层；12h 会话过期**原位重授权**（不清表单）。
- `GET /api/me` 拉取姓名、角色、权限点，落本地能力表 `CapabilitySet`。
- 403 统一话术：「你的角色无此权限，请联系综合运营部」，附当前角色名。

**不做**：任何角色管理、绑定（PC）。

**验收判据**
1. 三种失败（网络 / 授权拒绝 / 未分配角色）文案与出路不同，且「未分配角色」不出现「重试」按钮。
2. 会话过期后重新授权成功 ⇒ 原地回到原页面且表单内容保留（真机验证，录屏）。
3. 任何 403 响应都不会让界面白屏或崩溃（遍历 APP 白名单 18 个权限点对应的接口各打一次 403 的桩测试）。

### M04 扫码内核（B2）

**做什么**
- CameraX + ML Kit 连续扫码；识别成功立即震动 + 蜂鸣 + 绿边 + 大字回显尾 6 位。
- 三通道仲裁：相机 / HID 键盘（扫码枪以 `Enter` 结束，长度 27 且校验位通过才接受）/ 手输（先选父对象再输序号）。
- 确认卡：对象类型、人读码（`2-2-4-4-6-2-3-3-1` 分组）、关键三字段、确认/重扫/删除。
- 码解析走 `GET /api/recv/scan?code=…`：后端把「不存在」分成三类 —— 码非法 400 / 格式对但系统无此对象 404 / 业务规则拒绝 409，APP 的失败文案必须与这三类一一对应，不得合并成一个「扫码失败」。

**不做**：业务动作（由各业务模块在确认后调用）。

**验收判据**
1. 27 位码校验算法与后端 `spec/code-rules.json` 的 `sample_vectors` 全部一致（单测逐条）。
2. HID 输入长度不足 27 或校验失败 ⇒ 不提交、给红边 + 明确原因，**不静默丢弃**。
3. 手输路径**不能**输入裸 27 位（与 spec「不设独立短码」一致）。
4. 弱光/污损样本 20 张中识别成功 ≥18 张（真机实测记录）。

---

### M05 收货线（B3）

**做什么**
- S04 到货确认：选已有预报（GET `/api/recv/notices`）→ POST `/api/recv/arrivals`；**无预报拦截**（列出该车牌最近 3 条预报 + 一键拨号）。含退车 `POST /api/recv/trucks/:id/return`。
- S05 过磅：`POST /api/recv/trucks/:id/weigh`；毛重/皮重大数字键盘，皮重取该车历史。
- S06 建袋打码：`POST /api/recv/trucks/:id/bags` 批量建袋 → 连续打印；补打 `POST /api/recv/labels/reprint`（须原因）。

**不做**：预报新建/修改（PC）；车辆建档（PC）。

**验收判据**
1. 无预报时**不产生任何写请求**（抓包证明），且界面能拨号。
2. 建袋失败的中间态可恢复：部分成功时明确显示「已建 12 袋 / 失败 0 袋」，重试幂等不重复建。
3. 补打必须填原因，空原因时提交按钮禁用。

### M06 取样（B3 · 生产班组）

**做什么**
- S07 取样：`POST /api/sample/take`（份样 / 大样 / 保留样），扫对象码（车次 / 生产批 / 成品批）→ 确认卡 → 录取样量，提交。
- 取样人＝当前登录的生产班组账号，`sampled_by` 由会话决定，**不让手选**。
- 取样量默认 500g；份样数默认按目标对象的约定值，可改。

**不做**：留样入库（化验室 PC）、留样借还（化验室 PC）、样品交接确认（一期不做）、任何检测相关动作。

**前置依赖（阻塞真机联调，不阻塞开发）**
- 后端需按 `docs/BACKEND-REQ-01.md` 把 `sample.take` 授权给 `production`；在此之前调用返回 403，只能测 403 分支。

**验收判据**
1. 取样量与取样人默认值来自上一个动作/会话，页面必填项 ≤1。
2. 无 `sample.take` 权限的账号（收货员 / 管理层）登录时，取样入口**不可见**（不是点了才 403；质检不装 APP）。
3. 取样成功后样品列表（S13 追溯侧）能查到该样品编号与取样人。

### M07 生产线（B4）

**做什么**
- S09 建批：`POST /api/prod/batches`，默认沿用上一批配方/设备，批号由后端生成只显示。
- S10 投料：`POST /api/prod/batches/:id/feeds`；投料更正 `PATCH /api/prod/feeds/:id`（**限本班次内**，超时置灰并给 PC 指引）。
- S11 作业段：`POST /api/prod/batches/:id/operations`（开始/结束两点）。
- S12 成品打码：`POST /api/prod/batches/:id/fg-lots` + `POST /api/prod/fg-lots/:id/bags`。

**验收判据**
1. 投料进度（已投/应投）在扫码后即时更新，不需要手动刷新。
2. 跨班次时更正入口置灰且**不发请求**（时间判定用服务端时间，不用手机时间——防手机改时间）。
3. 建批页默认值来自上一批；若上一批不存在，全部字段为空且提交前必填校验逐项提示。

### M09 打印（B3 · 与收货同批，两级出口）

**做什么**
- S15 打印机管理：蓝牙扫描/配对/记忆、连接状态、信号、电量（若可达）、自检打印。
- 标签渲染：800×800 单色位图（100mm @203dpi），QR ≥6 dots/module；字段映射见 `design/labels/field-source.md`（随本模块出）。
- 三通道探测：TSPL `BITMAP` → ESC/POS `GS v 0` → 系统打印（打开服务端版式页）。**探测结果存本地，不硬编码**。
- **两级出口（D21）**：**B3-a**＝收货线 + 袋码标签的「系统打印」通道可走通；**B3-b**＝蓝牙直打（TSPL/ESC-POS 探测胜出者）通过自检。B3-a 不等 B3-b，先保收货上线。
- 自检页：100mm 标尺 + 当前通道名，用于验证「最大打印宽度 102 / 80mm」这一未决事实。

**验收判据**
1. 位图尺寸恒为 800×800；QR 模块 ≥6 dots（单测解析位图断言）。
2. 自检页必须能打印出完整 100mm 标尺（真机照片为证）。
3. 未连接打印机时，打印入口给「去连接」而不是直接失败。
4. 换机型只改 `PrinterProfile` 不改代码（代码中无 `203` / `800` 魔法数，走常量）。

### M10 出货线（B5）

**做什么**
- S12 装车归集：`POST /api/ship/shipments` + `POST /api/ship/shipments/:id/items`（逐袋扫码）；
- 出场 `POST /api/ship/shipments/:id/depart`。

**验收判据**
1. 同一袋重复扫两次 ⇒ 明确提示「该袋已在本次出货单中」，不重复计数。
2. 出货单汇总（袋数/净重）随扫码实时累加，无需刷新。

### M11 追溯与报表（B5）

**做什么**
- S13：正向 `GET /api/trace/forward`、反向 `/backward`、批次档案 `/api/trace/batch/:batchId`、袋谱系 `/api/prod/genealogy/bags/:code`；单屏纵向时间线，一屏看完「谁的料 → 哪批 → 测了什么 → 结论」。
- S14：`GET /api/rpt/:name` 只读报表卡片。

**验收判据**
1. 谱系任一节点可点开查看详情，且不出现任何写操作入口。
2. 报表只读，无导出按钮（管理层的导出在 PC）。

### M12 状态族与弱网（B2 起贯穿）

**做什么**
- 全局网络监听 + 顶部红条「网络中断 · 作业提交已暂停」+ 重试。
- 提交前联通探测；断网时**拦截在提交动作**，表单内容保留（不清空、不重扫）。
- 拦截页模板：原因 + 谁负责 + 一键拨号。
- 四类拦截页面：无预报、无车辆档案、无权限、码无效。

**验收判据**
1. 断网提交：不产生写请求、表单内容不变、恢复后一次点击成功（真机录屏）。
2. 四类拦截页都有「下一步」动作（拨号或去 PC 指引），无一处是纯文字死胡同。
3. 手机时间被改到未来/过去，不影响任何时效判定（全部用服务端时间）。

### M13 真机验收与发布（B5）

**做什么**
- 一台真机全流程走通：登录 → 收货（到货/过磅/建袋打码）→ 取样（生产）→ 建批 → 投料 → 成品打码 → 装车 → 出场 → 追溯。
- 门禁脚本 `scripts/check_app.sh`：lint + 单测 + 权限白名单扫描 + tokens 一致性 + APK 产物。
- 输出 `docs/ACCEPTANCE-APP.md`（逐条勾 + 录屏/照片路径）。

**验收判据**：门禁全绿 + 全流程录屏 + 四个拦截页截图齐备。

## 4. 全局机检判据（每一批都跑）

| 判据 | 强度 | 说明 |
|---|---|---|
| 权限白名单扫描 | **强** | 源码不得出现 33 项 PC 权限点及其 API 路径（含 `insp.*`、`retain.in`、`retain.lend`） |
| 页面清单扫描 | **强** | 新增 Screen 必须先在 `docs/SCOPE-APP.md` 登记 |
| tokens 一致性 | **强** | 生成物与 `tokens.json` 逐键比对 |
| 裸色值扫描 | **强** | `#RRGGBB` 命中数 = 0 |
| 断网不丢表单 | **强** | 单测 + 真机各一次 |
| 三态齐备 | **弱** | 文本级检查「每个 Screen 文件含 Empty/Intercept/Skeleton 引用」，只能证明有人在写，不能证明写对了——**不作为唯一依据** |

## 5. 我（WorkBuddy）每批做什么 / 不做什么

- **做**：出该批的逐屏设计（含三态）、写任务包、定判据、验收（复跑门禁 + 读实现 + 单点变异 + 还原核对）、维护 `docs/` 与 `design/`。
- **不做**：不写 `android/` 下的实现代码（与后端分工一致）；不替 mimo 调 CI。
